- 本地 Homebrew 源码安装及 `brew test` 通过，安装包签名、版本和自检通过；临时安装及 tap 已移除。首次构建发现模拟检查读取真实 GUI 修饰键状态会在 Brew 沙箱中等待，现注入物理标记快照，生产默认仍读取系统状态，并覆盖释放时保留真实 Shift 的行为。

## 当前设备与权限证据

用户确认遥控器为 RC003。系统只读枚举得到“小米蓝牙语音遥控器”，VID 0x2717、PID 0x32B8、Bluetooth Low Energy、Generic Desktop / Keyboard 接口；原始硬件地址、序列号、LocationID 和完整报告未写入记录。固件版本尚未读取。

运行 UI 已发现 1 个候选接口。用户报告已授权；系统“设备控制和数据访问”页也能看到 Remote2Prompt 已打开。期间曾出现运行进程与磁盘构建不一致，Security API 返回 -67034；重开一致版本后，应用曾实际显示设备控制“已授权”。后续构建会改变本地临时签名，因此需要按冻结的最终构建重新核验。

旧测试构建在授权后实际返回监听允许、设备控制允许；输入监控请求也曾返回 true。但这些结果不能证明存在独立的输入监控授权条目，之前界面的“已单独授权”标签有误。已改为有效监听能力显示，移除本应用的前置说明弹窗。缺少监听能力时直接调用 IOHIDRequestAccess 并打开对应设置，已具备时只提供设置入口。Apple DTS 解释辅助功能包含发送/监听能力，并建议 IOHIDRequestAccess 注册输入监控请求，见 [官方回复](https://developer.apple.com/forums/thread/828052)。本项目没有为制造弹窗重置 TCC、修改隐私数据库或伪造系统授权。

最后一次更新后，两项能力检查再次未允许，TCC 日志显示旧授权 cdhash 要求与当前构建不匹配（-67050）。已确认这是授权失效的证据；尚不能断言它是系统不弹窗的唯一原因。本机没有可用的代码签名证书，仍采用临时签名。当前构建中直接请求已实际执行并打开设置，但**没有观察到输入监控系统授权弹窗，也没有确认自动加入列表，故此项仍未修复验证**。请求 API 与参考项目相同，不能将替代说明框或设置页打开作为验收通过。

用户随后明确授权仅重置本应用输入监控记录。退出应用后执行 `tccutil reset ListenEvent dev.remote2prompt.app`，返回成功；相同构建重开请求后仍未观察到系统弹窗，设置列表也未自动出现条目，因此旧监听授权记录不是全部原因。接着增加公开 CGRequestListenEventAccess 的备用请求及只含权限状态的诊断，CLT 构建通过。实际请求记录为 `before=1 (Denied), hid=false, event=false, after=1`，没有将 false 当作授权成功。当前诊断构建固定后，再按同一授权范围重置一次，仅清理 ListenEvent / 本应用；等待人工点击复核，不重置设备控制或其他应用权限，不编辑数据库，不重启系统隐私服务。

用户人工点击后也报告没有系统弹窗，排除了仅由自动化点击造成的差异。完整核查无线麦的按钮、模型、HID wrapper 与打包签名：请求 API 相同；其开发临时签名显式固定 identifier 规则，而本机安装版使用 Apple 证书链及稳定团队身份。已补充可选证书签名与显式选择的稳定 ad-hoc 配置，默认仍不放宽规则，未对当前应用应用稳定 ad-hoc 设置。签名身份是已证实的版本授权漂移原因，尚不是本机未弹窗的完整结论。

授权排查期间，系统曾将相同 Bundle ID 的临时 Homebrew 构建作为设置授权的目标，导致 `dist` 构建与授权目标不一致。已移除临时 Brew 安装并通过公开 Launch Services API 重新注册当前 `dist` 应用；未重置或编辑权限数据库。后续权限验收只保留一个路径的构建，源码安装验证与交互授权验证分开进行。
