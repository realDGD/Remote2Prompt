# 功能探索与下一步建议

核查日期：2026-10-28。基于本项目 0.2.0 源码、实际 CLT/Homebrew 检查和相关应用官方资料。这里是建议清单，**不表示以下候选已实现或获准扩大产品范围**。无线麦的 139 个公开 issue 逐项处置见[完整评估](2026-10-28-issues-review.md)。

## 当前最值得补的是什么

先完成真实 RC003 的端到端语音和长时间运行验收，再扩充交互。当前最明显缺口是睡眠/锁屏生命周期、扫描永久等待、第三方 HID 工具占用提示、首尾音与系统输入恢复的真机证据。这些比再添加一个庞大自动化系统更接近软件的核心用途。

0.2.0 已有原生设置、常驻遥控器、三列手势、快捷键录入、左右修饰键、可跳过向导、便携配置、菜单输入选择，以及默认关闭的语音会话临时输入接管。已有代码不等于全部硬件验收：菜单真实切换、RC003 说话、输入法出字、AirPods/USB 抢占恢复和最低系统仍须分别记录。

## P0：先补稳定性和验收

| 工作 | 本项目源码证据与剩余问题 | 可验收结果 |
| --- | --- | --- |
| 睡眠、锁屏、快速用户切换的统一生命周期 | [RemoteMappingRuntime](../../Sources/Remote2PromptMac/RemoteMappingRuntime.swift) 监听 willSleep 后停止映射；[音频所有者](../../Sources/Remote2PromptMac/RemoteAudioRuntime.swift) 和 BLE 的扫描/重试没有统一锁屏门禁。不能据上游报告认定本机已复现唤醒风暴。对应 #513/#441/#240/#497/#231。 | 睡眠/非活动会话中停止相应连接活动、释放按键并恢复输入；后台维护唤醒不会恢复；用户解锁后一次性重新校验，配对失败不循环弹窗。长时间合盖保留系统蓝牙键鼠功能。 |
| 有期限的发现和有限退避 | [RemoteVoiceBluetooth](../../Sources/Remote2PromptMac/RemoteVoiceBluetooth.swift) 在 connect 后才启动 8 秒 timeout；discover 的扫描本身没有期限。已有查询系统已连接外设的路径，但仍可能无限扫描。对应 #631/#634/#733/#438。 | 扫描到期结束本轮；外设不在场时无忙循环；已连接但不广播可恢复；重连与正常语音不互相重启。 |
| 真机音频完整性和输入恢复 | 已有 120 ms 尾音、1 秒有界输出排空、输入读回和精确 UID 恢复，但 #297 是遥控器尚未传来的积压，App 排空不能解决全部情况。 | RC003 与 RC001 分别测开头、末尾、快速连按、60 秒终止、设备断开和 AirPods/USB 抢占；同一段输出保持顺序且结束释放正确，不采集保存输入文字。 |
| 明确区分占用、权限和输出链路 | #95/#105 是设备被 Karabiner 独占；#711/#308 说明音频到达不等于输入法已提交。 | 提示真正失败阶段；可复制脱敏摘要；不会要求重复授权来修复设备占用，也不把“写入成功”显示为“文字输入成功”。 |
| 长时间资源回归 | 没有上游全局 event tap 抑制架构，仍需检验 listener、timer、会话和回调释放。#476/#494 的维护者修复过程也说明“timer 共用”不代表查询只执行一次。 | 多轮连接/取消/休眠后资源计数回落，观察 WindowServer 和交互响应；内存只报测量值，不从较小 RSS 推断系统不卡。 |

## P1：适合当前产品的功能

1. **状态和电量**：菜单图标区分关闭、未连接、就绪、接收中和错误；文字/形状辅助颜色。电量通过实际支持的服务读取，附更新时间，失效显示未知。对应 #437/#618/#463。不能让过期值伪装实时。
2. **60 秒临近提示**：真实 ATVV 开始后计时，在接近型号上限时无声提示，不抢焦点；终止后提示松开再按。#355 的报告及维护者评论支持固件限制结论，本项目没有独立真机复验，不能宣传突破。对应 #679。
3. **纯麦克风模式与点按式工具适配**：当前 `wanted` 依赖语音触发开关，尚不能“只收音、不发键”。建议分别表达按住修饰键、起止各点按一次快捷键、不发按键三种语义，继续保持 RC003 实际按住才传音的边界。需要配置迁移、触发释放、输入接管和失败清理一起设计。对应 #698/#344/#347。
4. **少量常用预设**：添加空格、系统上一首/下一首、浏览器前进/后退，优先减少录入操作。空格当前可用自定义快捷键，系统切歌尚无预设；真正 keyDown 保持与重复敲击必须是不同模式。对应 #658/#386/#149/#584。
5. **按应用切换映射**：全局方案加前台 App 覆盖；手势开始时锁定动作，结束释放使用原方案。空覆盖应能区分继承与明确不执行。先手动方案，后自动匹配；不同时开出宏和第二套默认值。对应 #98/#704/#440/#394；上游 #98 评论说已实现，其后重复诉求不等同本项目也有。
6. **登录后台启动与脱敏诊断**：系统原生登录项、默认关闭，登录时不弹主窗口；诊断由用户主动导出，只含版本、架构、权限能力和错误阶段。不要原样附 UID、硬件地址、输入文字或语音。对应 #689/#102。
7. **虚拟回环健康检查**：读静音/音量、声道、UID 绑定和设备存活，未知属性保持未知。参考 #475，但不默认改实体麦克风/扬声器或强行放大正常音量；修复按钮需明确指向用户选定回环。

## P2 与暂不做

可再评估英文界面、更多遥控器型号、语音 F 键/系统听写适配、少量无内容自动化事件。这些都需要各自协议与目标工具证据，不能由上游 UI 选项推定可用。

不把以下事项并入当前路线：iOS/Windows/Apple Watch/Web 客户端、ASR/云模型、会员统计回眸、复杂宏、跨应用无界 AX 扫描、常驻防休眠、强行突破 RC003 锁存录音或固件上限。尤其 #132 的“松手后继续收音”与 #698 的“输入法保持会话、遥控器分段送音”不同；后者可独立评估，前者没有可靠硬件依据。

## 推荐下一轮顺序

先做 P0 的生命周期与扫描窗口，随后组织人在场的 RC003 真机矩阵；再做状态/电量和常用动作，接着设计纯麦克风及点按式触发，最后评估方案覆盖。调研文件不授权安装驱动、修改系统安全设置或自动实现所有候选。
