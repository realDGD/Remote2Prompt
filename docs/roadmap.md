# 路线图

状态按可观察能力标记。核心策略通过不代表真机功能完成；本清单的阶段顺序由依赖决定。

## M0：仓库与原生应用骨架

- [x] Harness 风格 AGENTS、Note 生命周期、项目技能与文档检查。
- [x] SwiftPM 工程、菜单栏、原生左栏设置、配置保存。
- [x] 语音键与输入优先策略及无 XCTest 检查入口。
- [x] CLT 构建与应用包验证脚本、本地 Homebrew tap 生成器。
- [ ] Intel / macOS 14 构建与 UI 验收。

## M1：先让真实按键可用

- [x] 确认当前 RC003 的 VID/PID、BLE 键盘接口和系统配对状态，建立合成协议样例。
- [x] 限定设备匹配、原生授权请求与设置入口、HID 接入及带恢复记录的原生按键抑制。
- [x] 实现单击、双击、长按与重复语义；原生映射读回不符时停止接管。
- [x] CoreGraphics 动作执行器与窗口内快捷键录入；schema 1 → 2 兼容迁移。
- [x] 四页设置、逐键示意图编辑与可重跑的真实按键设置向导；不包含组合动作、统计和回眸。
- [ ] 用真实遥控器及目标应用验证单击、双击、长按、退出和权限撤销。
- [ ] RC001 及不同固件的报告布局与兼容性验收。

M1 代码接入后继续推进设置与语音，当前见 [本轮验证](validation/2026-10-27-settings-and-voice.md)，历史见 [M1 记录](validation/2026-10-27-m1.md)。设备枚举不等于实际按键或语音成功。

完成标准：普通键映射可真实使用，退出后系统行为恢复，无重复动作或残留修改。

## M2：遥控器语音与左右 Control

- [x] CoreBluetooth / ATVV 初始化、通知、能力确认、超时与重连代码接入；不同固件仍待真机验收。
- [x] 合成样例验证 ADPCM，接入 PCM → 指定 UID 回环设备、缓冲和排空；MiRemoteV 静音输出检查通过，真实语音待验收。
- [x] 独立语音开关，Fn/左右修饰键事件、音频就绪门禁、排空释放与取消清理代码接入。
- [ ] 在微信输入法等实际目标应用测试左右 Control、Fn、快速连按和多设备抢占。
- [ ] 真机验证不丢首尾音、不出现粘住的修饰键，日志不泄漏语音或设备标识。

完成标准：按住遥控器说话，松开后在目标输入框得到实际识别结果。原生左/右 Control 兼容必须按应用分别记录，不能只凭 CGEvent 生成成功判定。

## M3：#435 输入优先策略接入

- [x] 按 UID 枚举和选择虚拟设备，正向区分实体、虚拟与未知输入；订阅默认输入和热插拔。
- [x] 接入 `AudioInputPriority`，分离已观测/已请求/已确认状态，读回确认、0.5 秒写间隔、同一意图三次失败后暂停。
- [x] 接入关闭、正常退出、向导、权限及音频失效恢复；自身通知、陈旧回调和模态退出路径已用模拟检查。
- [ ] 用 AirPods/USB 输入和至少两只遥控器完成 [硬件矩阵](testing.md) 验收。

完成标准：完整通过产品需求中的抢占、恢复、断连和手动选择场景，默认关闭时不修改系统输入。

代码接入与只读真实 CoreAudio 检查见 [M3 记录](validation/2026-10-27-m3.md)。本轮没有写真实默认输入，不能将 92 项自动检查当作 AirPods/USB 或多遥控器验收。

## M4：分发

- [x] 建立 public 源码仓库、公开前脱敏约定及 CLT/Homebrew CI。
- [ ] 确定项目许可证、发布用 Bundle ID 与首个发布版本。
- [x] 本仓库根目录维护固定完整源码 commit、归档 URL 与 SHA-256 的 Formula/Cask；通过显式仓库 URL 作为公开 tap。
- [x] 本机远端源码清洁安装、应用程序本体、`brew test`、卸载和 `--zap` 清理验证；详见 [安装记录](validation/2026-10-27-homebrew-app-lifecycle.md)。
- [ ] 干净 CLT 机器上 `brew install --build-from-source`、升级、卸载和应用程序入口验收。
- [ ] 独立评估 MiRemoteV/BlackHole 依赖和驱动分发；需要安装驱动时提供单独、显式的流程。
- [ ] 如需公开二进制分发，再接入 Developer ID 签名、公证与下载校验。

源码、Homebrew 配方与 CI 在同一仓库维护。版本固定源码；不在本流程中安装驱动或重启系统音频服务。
