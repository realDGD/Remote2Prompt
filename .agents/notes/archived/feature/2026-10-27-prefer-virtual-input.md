# Agent Note: 遥控器在线时优先虚拟输入

Status: implemented
Archived: 2026-10-27

## Problem

当遥控器仍在线时，AirPods 或新 USB 麦克风可能抢走系统默认输入，导致使用默认输入的语音工具无法听到回环设备中的遥控器声音。

## Decision

原生“系统输入优先”开关默认关闭，仅在用户开启、音频链路初始化成功、HID 接管及权限有效时保持所选回环为默认输入。实体输入抢占时记录其 UID 并重选回环；断连、关闭、权限/音频失效、向导、休眠和正常退出时有条件恢复最近仍可用实体输入。不修改默认输出。

核心 `AudioInputPriority` 分离观测、请求与确认：写入被接受且当前请求读回匹配后才取得恢复所有权；初始已选虚拟输入不接管，恢复失败保留重试依据。MiRemoteV / BlackHole 用固定驱动 UID 和双向声道确认可优先身份，实体恢复只接受已明确识别的物理传输类型，未知、虚拟及聚合输入不参与回退。AudioDeviceID 不进入核心、配置或日志，最近实体 UID 与所有权只保存在当前进程内。

`CoreAudioInputSystem` 管理默认输入、设备列表及设备属性监听，写入前按 UID 重新解析目标并再次比较当前输入。`InputPriorityCoordinator` 在 MainActor 串行处理快照和待确认写入：1 秒读回窗、0.5 秒全局写间隔、同一意图最多三次失败，状态变化后可重新评估，也提供显式重试。通知只触发新观察，不重复提交已有请求；回调带生命周期代际，停止后不能重启资源。监听器、合并计时器和订阅由适配器显式清理。

`AudioInputPriorityRuntime` 接入真实音频/HID 就绪，独立于普通映射开关；设置分别显示实际、最近请求、最近确认及恢复目标。正常退出为异步确认和重试保留 3.5 秒预算，无待恢复工作直接退出；需要等待时使用 AppKit 模态运行循环，避免主 GCD 队列与退出过程互相等待。完整语义由 [产品需求](../../../../docs/product.md) 维护。

## Alternatives considered

**总是强制虚拟输入。** 会覆盖用户主动使用其他麦克风的选择，因此仅在显式开关打开且遥控器就绪期间接管。

**只在初次连接切换一次。** 无法处理 AirPods 或 USB 后续抢占，不能满足 #435。

**断开时永远恢复首次输入。** 会丢掉用户后来选择的 AirPods；优先恢复最近仍可用的实体 UID。

## Consequences

核心、系统适配器、运行时和原生设置均已接入；模拟覆盖请求拒绝/不生效/延迟、最新实体选择、源变化、通知风暴、热拔插、多个就绪来源最后断开、模态退出和失败恢复。真实只读目录检查确认注册和清理监听器、默认输入/输出保持不变；本轮未切换真实默认输入。真实 AirPods/USB、遥控器断连及多遥控器矩阵仍待验收，不能由本 Note 的 implemented 推断这些硬件结果通过。详细证据见 [M3 验证](../../../../docs/validation/2026-10-27-m3.md)。

CoreAudio 不提供原子比较并写入，最后一次读回与外部选择之间的竞争不能绝对排除；确认超时不猜测成功。没有实体目标、系统拒绝恢复或驱动异常时显示错误并限制重试。强制结束和系统崩溃无法执行退出恢复，下次启动也不凭虚拟默认输入猜测旧所有权。当前生产音频仍限一个所有者，多来源语义已用模拟集合验证，真实多遥控器支持与验收保持独立。
