# Agent Note: 设备原生键接管与可恢复租约

Status: implemented

## Problem

遥控器可能暴露多个 HID 接口；仅读取按键并注入动作会与系统原生行为重复，电源键尤其可能先触发休眠。进程意外退出也不能把用户的原有设备映射遗忘。

## Decision

`VoiRemoteMac` 隔离 macOS 适配器。`NativeKeyLease` 使用 Apple TN2450 介绍的 IOHIDServiceClient 属性 API，只为 VID/PID 0x2717/0x32B8 的服务中属于遥控器的 usage 写入零目标，并读回验证。每次按键执行前及权限轮询时核验服务覆盖；新接口或外部改动使验证失效时停止接管。

原始 HID report 通过限定设备的键盘接口读取，不创建吞键的全局 Event Tap。恢复日志位于本机 Application Support/VoiRemote/HIDRecovery.json，包含同次系统启动的瞬时服务 ID 和接管前的所属映射，在首次设备写入前原子保存。启动、退出、关闭功能、断连、权限失效与失败时恢复；恢复失败保留记录供重试。其他软件后来修改的源映射和不属于本应用的映射保留。

恢复日志 v2 另外保存本次接管源范围，兼容旧 v1 全键范围。语音触发拥有独立开关；只开语音时只接管 F5 usage，普通映射开而语音关时不接管语音键。切换范围先停止并恢复原租约，再获取新范围，模拟检查覆盖跨实例恢复。

`SystemActionSender` 成对构造键盘与媒体事件；语音使用 flagsChanged、左右键码和设备侧修饰标记。物理键已按住时拒绝语音合成接管；权限丢失后仍尝试释放。动作与按键发送提供注入出口，自动测试不向桌面实际发送输入。

释放时将本次修饰键家族从全局 flags 快照中移除，再按真实物理键状态重建，保留另一侧及其他家族。这样不会把可能仍包含合成 hold 的快照原样发回；Fn 同样单独清除与释放。

设备控制授权包含事件监听能力，输入监控不以必须出现独立授权条目作为启动前提；实际 HID 打开失败仍会回滚租约并停止，不把授权 API 的返回值当作报告接收成功。输入监控先使用 IOHIDRequestAccess，未允许时再使用 CGRequestListenEventAccess，前者依据见 [Apple DTS 回复](https://developer.apple.com/forums/thread/828052)。请求等待应用激活，并注册当前 bundle 的 Launch Services 路径。监听已允许时只提供设置入口；首次或未知状态请求后保留焦点让系统提示出现，原状态已经拒绝时才直接打开设置。不插入本应用的说明弹窗，也不承诺再次出现系统弹窗。公开检查无法区分监听来自设备控制还是单独输入监控，界面只显示有效监听能力。返回应用时自动刷新。权限日志只记录请求前后枚举值和两个请求返回值，不记录按键或设备内容。

设置向导可临时启用同一 HID 链路，但不执行普通映射或发送语音修饰键；进入前释放正在发送的按键，退出后恢复用户的启用状态。`SetupInputCheck` 只接受本次阶段内、同一来源成对的按下和松开，语音不计为普通键，断连或接管失效后清除证据。检测结果仅在内存保存，不作为音频或目标应用输入成功的证明。

发现阶段通过 IORegistry 属性计数，不为列出设备创建 HID plug-in/user client。权限同步 IPC 由串行后台 PermissionProbe 执行，最多一个状态查询在飞，主线程只消费结果。不变的状态不重复发布。系统拒绝且不再提示时提供真实设置页与非模态拖入图标引导，图标拖放是当前 bundle URL，由用户完成授权；引导不伪装系统框。

## Alternatives considered

**仅独占一个 HID 接口。** 不能保证同设备其他接口没有原生事件，不足以作为危险键抑制依据。

**在 HID 报告后的短窗口按键码吞掉系统事件。** 缺乏可信设备来源关联，可能吞掉用户同时操作的普通键盘按键。

**全局 hidutil 映射或退出时覆盖整个数组。** 会扩大到其他键盘或丢失外部软件的设置，因此按服务、按所属源合并恢复。

## Consequences

接管之前可以验证映射写入和恢复准备状态；失败不会继续发送映射动作。同次启动内的中断可恢复，重启后的旧服务 ID 不应用于新服务。读回证明属性设置结果，不能代替真机验证固件的实际原生事件抑制；RC003 真机验证和 RC001 兼容性按验证记录分别陈述。强制杀进程后、应用再次启动之前仍可能暂时保留原生键抑制，用户可重开应用恢复；没有常驻特权 helper。
