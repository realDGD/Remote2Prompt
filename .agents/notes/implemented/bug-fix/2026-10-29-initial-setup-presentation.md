# Agent Note: Initial setup presentation

Status: implemented

## Problem

向导只有侧栏/菜单的手动入口。清洁安装0.2.8后，虽然映射、语音和虚拟麦克风正确关闭，却直接进入按键页，缺少首次使用引导。安装后自检之前只验证配置格式，没有覆盖首次启动流程。

0.2.9补齐自动展示后，用户在授权弹窗点击退出重开，旧进程仍在正常运行。隔离预览复现向导打开时Command-Q无效，跳过向导后才能退出。AppKit默认sheet阻止终止且不咨询退出代理；另一个问题是把“展示”当“完成”会丢失权限重启后的向导。

## Decision

设置窗口的SwiftUI层级就绪后调用 `ConfigurationStore.presentInitialSetupIfNeeded`。没有本地配置且尚未明确结束首次向导，或有进行中的向导时自动展示；有配置且无进行中向导的升级/导入不弹。损坏/未来配置保留原始数据，不用向导覆盖。

展示只写本地 `setup.pending.v1`；保存成功或明确跳过配置才写 `initialSetup.finished.v1` 并清除pending。进程退出和视图消失不能清除pending，权限重开后回准备页，不保存未确认草稿。两个标记均不进入schema5导出，也不代表硬件通过。0.2.9旧展示标记无法区分主动跳过与中断，无配置时重新引导一次；实际完成后删除旧键。zap清理整个本应用偏好域。无设备原生预览支持首次流程，其他smoke入口保持隔离。

仅向导sheet设 `preventsApplicationTerminationWhenModal=false`，用NSView挂载到真实窗口，卸载时恢复原值。这样终止请求进入既有按键释放和输入恢复清理，不增加自动重启子进程或系统权限重置。参考[Apple说明](https://developer.apple.com/documentation/appkit/nswindow/preventsapplicationterminationwhenmodal)。

继续沿用现有四步、草稿、跳过配置和跳过检查；不自动发起权限请求、保存草稿或开启语音。运行时仍由应用delegate拥有，首次向导不把服务订阅重新绑定到窗口。

## Alternatives considered

- 每次启动检查“是否开启映射”：跳过或只用麦克风的用户会被反复打扰，不采用。
- 只记录已经展示：不能区分中断和完成，会使授权重启后向导丢失，替换为pending/finished。
- 用守护进程强制重启：不能修复AppKit在sheet前拒绝退出，且会改变普通退出语义，不采用。
- 把“已展示”写入可导出的配置：导入另一台Mac会混淆本机首次使用，不采用。
- 在App初始化前直接置sheet为true：可能早于窗口层级可展示时机，改在设置视图task中判断。

## Consequences

尚未保存或明确跳过时重开会继续引导；展示过本身不构成完成。CLI自检用实际ConfigurationStore与一次性偏好域覆盖首次、中断、跳过、手动恢复、旧展示标记迁移、升级、损坏及导入；独立CLT构建与自检通过，不触及生产设置或硬件。

独立硬件关闭预览实际自动展示准备页，跳过后功能保持关闭；手动重跑可进入配置、跳过检查并明确显示“已跳过检查”，保存后回到设置。没有点击系统授权或启用音频。此预览验证原生sheet，仍与安装版首次体验、真实遥控器及最低系统验收分开记录。

退出回归使用同一原生预览：修复前向导打开时Command-Q无效，跳过后才可退出；修复后在向导未关闭时Command-Q正常结束进程，未强杀。该结果验证AppKit sheet阻挡的修复，不将普通退出等同真实TCC系统按钮的再次验收。

0.2.9经远端HTTPS源码清洁安装后，原生安装版首次打开也自动显示准备页；只读核对展示标记已写而配置尚未保存，应用留在向导供用户继续。实际来源和安装结果见[发布记录](../../../../docs/validation/2026-10-29-source-release.md)，未代替真实设备/输入法验收。

0.2.10安装版另行通过向导保持打开时退出、真实进程结束、pending保留且finished未写，以及重开同一路径后向导恢复。真实TCC按钮仍单列待用户复测，不把普通Command-Q验收等同系统重新拉起。
