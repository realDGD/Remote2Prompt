# Agent Note: Initial setup presentation

Status: implemented

## Problem

向导只有侧栏/菜单的手动入口。清洁安装0.2.8后，虽然映射、语音和虚拟麦克风正确关闭，却直接进入按键页，缺少首次使用引导。安装后自检之前只验证配置格式，没有覆盖首次启动流程。

## Decision

设置窗口的SwiftUI层级就绪后调用 `ConfigurationStore.presentInitialSetupIfNeeded`。没有本地配置、没有持久化展示标记且设置可读时自动展示向导；已有配置的升级或导入不弹。损坏/未来配置保留原始数据，不用向导覆盖。

本地 `initialSetup.presented.v1` 在自动或手动展示时记录，不进入schema5可移植配置，也不代表权限、按键或音频已经通过。用户跳过后不会在重开窗口或重启时反复弹出；仍可从两个手动入口重跑。清洁卸载zap会连同偏好域清除此标记。无设备的原生检查入口可展示首次向导，其他专用smoke入口保持各自的隔离目标。

继续沿用现有四步、草稿、跳过配置和跳过检查；不自动发起权限请求、保存草稿或开启语音。运行时仍由应用delegate拥有，首次向导不把服务订阅重新绑定到窗口。

## Alternatives considered

- 每次启动检查“是否开启映射”：跳过或只用麦克风的用户会被反复打扰，不采用。
- 把“已展示”写入可导出的配置：导入另一台Mac会混淆本机首次使用，不采用。
- 在App初始化前直接置sheet为true：可能早于窗口层级可展示时机，改在设置视图task中判断。

## Consequences

展示过但未保存也不再自动打扰，故异常关闭前已展示的用户应从手动入口重跑。CLI自检用实际ConfigurationStore与一次性独立偏好域覆盖首次、跳过、重建、手动重跑、升级、损坏数据及导入，不接触生产设置或硬件；独立CLT构建和自检已通过。

独立硬件关闭预览实际自动展示准备页，跳过后功能保持关闭；手动重跑可进入配置、跳过检查并明确显示“已跳过检查”，保存后回到设置。没有点击系统授权或启用音频。此预览验证原生sheet，仍与安装版首次体验、真实遥控器及最低系统验收分开记录。
