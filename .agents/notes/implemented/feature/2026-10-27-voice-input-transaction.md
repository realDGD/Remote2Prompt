# Agent Note: 按住语音键临时切换系统输入

Status: implemented

## Problem

在线期间持续优先回环会影响用户平时使用系统麦克风。用户明确改为：未按下不干预，按下强制使用遥控器输入，松开后恢复按下前状态。因此旧“最近实体输入”不能作为恢复依据，连接 ready 也不能触发切换。

## Decision

保留默认关闭的 `preferVirtualInput` 配置，不改变已保存配置格式。`AudioInputPriorityRuntime` 的 ready 只代表可用条件，只有 `beginVoiceSession` 才建立活动来源。核心按语音事务捕获当时默认输入 UID，按住期间外部抢占不修改该快照；松开并完成尾音排空后恢复精确原输入，包括仍可用的其他虚拟或未知传输设备。原设备消失才使用稳定实体回退，无目标则显示未恢复。

`InputPriorityCoordinator` 区分请求和读回确认。显式按下/结束边界立即尝试写入，重试和按住抢占至少间隔 0.5 秒，同一意图最多三次失败；读回窗为 1 秒。松开后的新系统选择优先于旧恢复目标，确认窗内已接受的旧延迟写入发生时，补偿回到该新选择。旧事务未结束的快速重按保留返回基线，不将本应用临时选择的回环误认成原输入。

`RemoteAudioRuntime.prepareInput` 在输入确认后才发送锁定的触发键；等待时保留最多 32000 个单声道 PCM 样本，不存盘。松开早于确认则取消门禁，代际阻止旧回调补发触发键；成功会话仍沿用 120 ms 尾音及有界排空，随后释放触发键并恢复输入。只有 HID 按下能开始，ATVV open 不再创建或重试会话，等待输入切换期间也暂停普通映射。

断连、权限/音频失效、向导、休眠和退出均撤销事务。正常退出保留 3.5 秒恢复预算，最终未恢复错误不被停止后的更新清除。只写系统默认输入，不写默认输出，不记录原始设备标识或语音。当前生产音频仍限制单一所有者。

## Alternatives considered

**遥控器在线期间持续优先。** 已被用户的新操作要求替代，旧决定保存在 [归档](../../archived/feature/2026-10-27-prefer-virtual-input.md)。

**松开时恢复按住期间最近出现的实体输入。** 会把临时抢占误认成按下前状态，也无法恢复原先的其他虚拟输入，因此采用精确快照。

**先发送触发键，再异步切输入。** 目标输入法可能已经打开旧麦克风，因此先等读回；等待窗口内保留少量早到音频。

**物理松开立即恢复，不等待尾音。** 容易截断已收到但尚未输出的音频，因此将恢复放在排空和触发键释放后。

## Consequences

核心策略、真实 CoreAudio 写入口、协调器、音频会话与设置已接入。63 项核心和 53 项 macOS 检查通过；其中切换和恢复使用模拟系统，不写真实默认设备。详细证据见 [语音事务验证](../../../../docs/validation/2026-10-27-voice-input-session.md)。真实 RC003、输入法和 AirPods/USB 切换仍未验收。

CoreAudio 没有原子比较并写入，也不能撤回已接受的异步请求；确认窗口外才执行的驱动请求、强制结束和系统崩溃仍不能保证恢复。输入法若固定使用某个麦克风，应单独核对其设备选择；系统默认输入变化不证明目标输入法已开始识别。快照和所有权仅保留在当前进程内，不在下次启动猜测上次会话状态。
