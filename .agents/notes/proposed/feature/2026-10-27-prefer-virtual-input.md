# Agent Note: 遥控器在线时优先虚拟输入

Status: proposed

## Problem

当遥控器仍在线时，AirPods 或新 USB 麦克风可能抢走系统默认输入，导致使用默认输入的语音工具无法听到回环设备中的遥控器声音。

## Proposal

增加默认关闭的输入优先开关，在至少一只遥控器 ready 且音频链路健康期间保持所选虚拟输入。记住后来成为默认的实体设备，最后断连或关闭开关时恢复最近仍可用的实体输入，不修改默认输出。

当前 `AudioInputPriority` 已将观测、切换请求和确认分开：只有请求与读回匹配后才取得恢复所有权；初始已选虚拟输入不接管，恢复失败保留所有权，未知输入不作为实体回退。CoreAudio 目录、监听和默认输入专用写入，以及注入式协调器已接入：1 秒读回窗、0.5 秒写间隔、同一请求最多三次。模拟检查与只读真实目录检查通过，应用接线和正常退出的有界恢复仍在实施；真实 AirPods/USB 与遥控器矩阵尚未验收。完整语义由 [产品需求](../../../../docs/product.md) 维护。

## Alternatives considered

**总是强制虚拟输入。** 会覆盖用户主动使用其他麦克风的选择，因此仅在显式开关打开且遥控器就绪期间接管。

**只在初次连接切换一次。** 无法处理 AirPods 或 USB 后续抢占，不能满足 #435。

**断开时永远恢复首次输入。** 会丢掉用户后来选择的 AirPods；优先恢复最近仍可用的实体 UID。

## Acceptance criteria

真实完成内建输入 → 遥控器 → 虚拟输入 → AirPods 抢占 → 恢复虚拟输入 → 最后一只断连 → AirPods 的序列。另行验证多遥控器、设备移除、开关关闭、退出、写入失败和自身通知无循环。纯策略通过不足以迁移状态。

## Risks

系统写入可能失败，属性回调可能重排，驱动和回环设备的身份必须可靠判断。恢复只能在本应用仍拥有虚拟默认输入时执行，不能覆盖最后断连后新的手动选择。
