# Agent Note: Sleep-aware remote recovery

Status: proposed

## Problem

0.2.0 的映射所有者在 willSleep 停止按键，但音频和 BLE 生命周期未统一覆盖锁屏/解锁与非活动登录会话。BLE 扫描自身没有期限，初始化超时只从 connect 开始。无线麦 #631/#513 等报告提供相似风险线索，尚未在本项目真机复现。

## Proposal

系统睡眠/唤醒和有界扫描已接入，实际范围见[已实现决策](../../implemented/feature/2026-10-28-system-sleep-audio-lifecycle.md)。本提案继续保留锁屏、解锁、用户会话切换和维护唤醒的未完成范围。

为映射、音频与 BLE 共享可观察的运行条件；锁屏、睡眠和用户会话切换时暂停相关资源，完成原有释放与输入恢复。只在真正可交互的用户会话恢复后重新验证一次，不把后台维护唤醒等同解锁。发现窗口需要有期限，失败退避必须有限、可取消，不静默重新配对。

## Alternatives considered

- 只延长固定重连间隔：不能解决无限扫描和恢复事件顺序。
- 忽略设备或关闭系统蓝牙：影响其他设备和配对状态，不作为软件自动行为。
- 将全部系统唤醒归因应用：缺少证据，不采用。

## Acceptance criteria

模拟覆盖睡眠/屏幕/解锁顺序、重入、取消与扫描到期；真实 RC003 验证不在场、已连接不广播、合盖长时间运行、蓝牙键鼠及输入恢复。资源、错误状态和触发键成对清理，不保存设备身份日志。

## Risks

系统蓝牙 HID 本身仍可能唤醒机器，应用不能保证阻止全部唤醒。锁屏通知可靠性、快速用户切换与输入设备恢复需独立验收；未接入前不将本 Note 移为 implemented。来源与候选范围见[调研](../../../../docs/research/2026-10-28-feature-exploration.md)。
