# Agent Note: Explicit voice output modes

Status: proposed

## Problem

当前“关闭虚拟麦克风”提供的是纯触发键路径；“只转发声音、不发送触发键”尚未实现。这两种需求相反，不能把voiceEnabled直接关闭作为纯麦克风模式：现有音频wanted、HID语音租约及会话门禁都依赖它。

[上游#698](https://github.com/HD838A/remote-mic-app/issues/698)提出由另一个按键开始/结束输入法，遥控器语音键只控制分段送音。报告者仅在Windows与微信输入法验证，明确没有macOS实测。因此这里只做可执行设计，不声称Mac兼容，更不声称突破RC003单段上限。[#355的后续实验](https://github.com/HD838A/remote-mic-app/issues/355#issuecomment-5552588053)也不支持自动续租/重开。

## Proposal

最小下一阶段只增加两种明确的输出方式：`holdModifier`沿用当前左右修饰键按下/释放；`microphoneOnly`完全不向系统发送触发事件。起止各点按一次的toggle方案留到单独阶段，不能把“不发按键”和“起止点按”合成一个选项。

建议未来schema5增加`voiceOutputMode`，默认holdModifier；保留voiceTrigger作切回时的选择。voiceEnabled继续作为遥控器语音总开关，界面名称需一并改为“启用遥控器语音”，不再暗示它只控制按键。旧schema4所有开关和左右键原样保留，迁移不自动开启音频、纯麦克风或系统输入优先；便携导入继续关闭能力。选择microphoneOnly而虚拟麦克风尚未配置时，明确提示先配置音频，不回退成Fn，也不静默启用设备。

接口在发送边界区分“会话允许开始”和“实际持有合成键”：开始返回一个锁定本次输出方式的会话令牌，结束只释放该令牌实际发送过的键。microphoneOnly的成功开始不需要虚构按下事件；取消仍要结束输入事务、停止/排空音频并恢复原输入。不能以VoiceSession.heldTrigger是否为空判断语音是否活动。

对应接线：

- Core：模式、配置迁移及锁定的输出会话；holdModifier的左右键语义保持不变。
- Mac：HID语音源仍需受控租约；音频按住期间暂停普通遥控器映射；SystemActionSender只在holdModifier调用。切换模式先取消旧会话，不能释放新模式下猜测的键。
- 输入事务：两种模式都遵守用户的“按下快照、确认后开始、松开排空后恢复”。不因为第三方还在录音就延长系统接管。
- 时限提醒：只由真实ATVV段驱动，与是否发键无关；仅发送触发键而没有遥控器音频时不显示。键盘直接触发输入法仍不接管系统输入。
- 设置：输出方式与左右键选择放在现有语音卡；microphoneOnly时隐藏左右键选项但保留其值，链接到虚拟麦克风设置。避免再叠多层菜单。

关键边界：如果输入法持续录音且跟随系统默认，遥控器松手后恢复实体输入，它可能继续接收实体麦克风。**“遥控器停止送音”不等于“第三方录音已停止”或“所有麦克风都静音”。** 需要持续分段识别的用户应自行在输入法选择固定回环并验证；应用不读取/修改第三方私有设置。默认输入恢复语义不能为此偷偷改变。

## Alternatives considered

- 只把voiceEnabled设为false：同时关闭现有语音租约和音频路径，无法表达只收音。
- 往VoiceTrigger枚举加入none并到处跳过：容易让没有实际按键的会话跳过清理，且UI仍把“无键”当作一种键。独立输出方式更清楚。
- 一次加入hold/toggle/none三种：toggle在外部手动停止后无法可靠判断状态；盲目补一次快捷键可能反而开始录音，暂不合并。
- 为连续识别让系统默认长期停在回环：违反用户已确定的松开恢复语义，不采用。
- 软件自动续租或定时重开麦克风：上游实验未成功，增加静默录音与粘键风险，不采用。

## Acceptance criteria

1. schema1–4迁移逐字段保留现有开关、左右键及映射；未来字段未知时仍拒绝覆盖。导入不启用能力。
2. holdModifier保持现有成对事件、物理修饰键冲突检查及侧别；microphoneOnly的开始/结束/失败/退出均生成零个系统触发事件。
3. 关闭虚拟麦克风时，现有纯触发键路径照常；microphoneOnly则报告音频未配置，不能误发Fn。
4. 同一物理段锁定方式；中途切换、快速重按、延迟输入确认、旧排空/回调均不能重复发键或漏释放。
5. microphoneOnly仍要等待系统输入读回；松开/取消/断连/权限失效/休眠/退出正确释放输入事务，晚到写入能按现有边界补偿。
6. 真实ATVV START才建立时限起点；microphoneOnly也能提醒；未知停止原因中性显示，不自动续开。
7. 模拟“外部录音继续＋系统恢复实体”的场景，明确不宣称静音；真实Mac上分别验收输入法固定回环和跟随默认，不录制内容。
8. 另一普通键可配置启动/停止用的快捷键；不能据可录入认定第三方接受，也不自动把默认映射替换成toggle方案。
9. 目标输入法实际识别、首尾音、长段分段、重连与休眠需要RC003和用户配合；普通检查不访问真实设备。

## Risks

此候选跨配置/策略、Mac会话适配器、设置和真机验收，建议至少按“迁移与会话策略→发送/音频接线→UI与兼容验证”三次可审阅提交推进。需要人在场的Mac、RC003和目标输入法；不用未经测试的Windows经验估计Mac成功率或工期。

现有ATVV停止回调缺少可用段标识，同一连接晚到事件仍需真实顺序证据。不能为赶进度加入任意忽略窗口或轮询第三方焦点。此Note只细化方案，不授权实现、发布、安装或改变当前0.2.7行为。
