# Agent Note: Input catalog startup recovery

Status: proposed

## Problem

输入适配器首次启动失败后，运行时仍存在，但菜单“刷新输入设备”与周期刷新只调用 refresh；协调器要求 running，导致后续设备服务恢复也无法通过菜单重新注册监听。实际类加模拟适配器的探针已复现；不是本机 CoreAudio 故障的真机报告。

## Proposal

让显式目录刷新在硬件允许、未关闭的条件下，先调用现有幂等 start，再 refresh。已运行时 start 不重复注册，不重置输入事务或失败预算；初始化未成功才允许重新启动。周期刷新继续只读，不加入自动无限初始化重试。

隔离候选已用同一探针验证可恢复两项模拟输入，尚未修改生产源码或安装版。无设置字段变化，无配置迁移；不修改 Formula 固定来源。记录和命令见 [运行时审查](../../../../docs/research/2026-10-28-idle-runtime-audit.md)。

## Alternatives considered

- 直接调用 retry：会清除写入失败计数与意图，目录刷新不应改变语音事务的保护边界。
- 周期性反复调用 start：可能持续重试系统失败；先保留用户明确发起的恢复入口。
- 只能退出重开：可作为临时处置，但让“刷新”在该状态下没有作用。

## Acceptance criteria

- 首次 start 失败、随后恢复时，显式刷新重新注册一次并更新目录；仍然失败时保留可理解的失败状态。
- 已运行时连续刷新不重复注册，不重置写入失败上限、不改快照和所有权；关闭中与关闭后均不再启动。
- 重复初始化失败不会保留 listener；没有语音且没有用户选择时不写系统输入。
- 接入后运行相关适配器检查与 CLT 构建；真实故障或安装版菜单补验单独记载，不用模拟结果代替。

## Risks

start 失败后的部分资源清理依赖 AudioInputSystem.stop 的契约。模拟中同步回调与真实 CoreAudio 异步回调不同，需保留重入防护与关闭条件；该方案不处理所有中途服务重启问题。
