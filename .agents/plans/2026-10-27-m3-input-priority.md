# M3 默认输入优先 Implementation Plan

本轮由当前 agent 直接实施，沿用用户已明确的需求和分阶段提交授权；按项目约定不另启设计审批、子 agent 或整套流程。不推送远端。

**Goal:** 接入 #435：显式启用且遥控器音频就绪时保持所选虚拟输入，失去就绪、关闭或退出时有条件恢复最近实体输入。

**Architecture:** 核心分离观测、请求与确认，只有成功写入并读回后取得恢复所有权。macOS 适配器按 UID 枚举和重新解析设备，监听默认输入与拓扑变化；串行协调器管理待确认写入、限频和重试。应用用真实音频/HID 就绪驱动，并为正常退出等待有界恢复。

**Tech Stack:** Swift 6 / SwiftPM、macOS 14+、CoreAudio、Combine、SwiftUI/AppKit、独立 Command Line Tools。

**Spec:** [产品需求](../../docs/product.md)、[M3 路线图](../../docs/roadmap.md)。

## Global Constraints

- 默认关闭，未开启不接管输入；不改系统输出，不安装驱动，不创建证书，不改全局 xcode-select。
- UID 保持于设置和适配器边界；AudioDeviceID 不进入核心或持久设置。真实标识不写日志。
- MiRemoteV / BlackHole 采用固定驱动 UID 与声道验证；未知、虚拟或聚合输入不能作为实体恢复目标。
- UI smoke 和普通自动检查不写真实默认设备；真机切换、AirPods/USB、多遥控器验收与模拟结果分别记录。

## Review Focus

- 初始已经选择虚拟输入时不取得未经证明的恢复所有权；失败或超时不伪报成功。
- 自身通知不重复写入；通知风暴受全局最小间隔和同一请求最多三次限制。
- 待确认期间关闭或退出：先处理本次已发出的写入，再恢复；旧回调不能重启资源。
- 实体设备消失、未知传输类型和其他虚拟设备不产生不安全回退；默认输入读取失败时不写。
- 退出/音频失效/权限失效只恢复仍由本应用接管的虚拟默认输入；外部后来的实体选择保留。
